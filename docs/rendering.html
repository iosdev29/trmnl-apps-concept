How the firmware renders

The app sends a tree of components; the firmware draws it.

TRMNL UI 1.0 · App API v1 · TRMNL X · TRMNL OG

At the end of each press the SDK turns body() into a small tree and sends it to the firmware with one call. The firmware lays it out, draws it with its fonts in the TRMNL design, refreshes the e-paper and tells the app what only it can know, such as the page count of a Reader(_:_:).

{"t":"layout","c":[
  {"t":"title","s":"Groceries"},
  {"t":"list","sel":1,"items":["Oat milk","Bread"]},
  {"t":"bar","s":"Groceries","i":"2 items"}
]}

In the product the renderer is LVGL with a TRMNL theme; in the simulator it is a JavaScript renderer with the same rules. The format is part of render(_:_:).
